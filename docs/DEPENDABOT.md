# Dependabot workflow\n\n## How it works\nDependabot scans the `package.json` and `package-lock.json` files in the repository root.\nWhen newer versions of any npm package are found, it opens a pull request that bumps the version\nand runs the repository's CI workflow.\n\n## Schedule & ecosystem\n- **Ecosystem:** npm\n- **Check frequency:** daily (GitHub Actions runs every day)\n\n## Security updates\nAll dependency types are allowed (`dependency-type: all`), so security‑only updates are created\nautomatically in the same way as regular version upgrades.\n\n## Escalation process\n1. **Alert** - If a Dependabot PR fails CI, the team is notified in the `#devops` Slack channel.\n2. **Review** - A maintainer reviews the change, ensures no breaking impact, and re‑runs CI if needed.\n3. **Merge** - After verification, the PR is merged.\n   *If the change is critical, the release manager must approve before merging.*\n\n## Merging requirements\n- PR must pass all status checks (including `dependabot/pr` if branch protection is enabled).\n- At least one reviewer must approve the PR.\n- The main branch must be up‑to‑date with the target branch before merging.\n
